## Interpretation

This is a healthy run: every UI file imports from MUI, and there are no invented components, invented props or competing UI libraries. All 9 findings are in two areas, token discipline (8) and one missing accessible name.

- Four of the eight token findings are hardcoded values that already exist in src/theme.ts: the green border in ShiftCard, the amber and amberLight pair in StatusChip, and the green background in VolunteersPage. This usually means the code was written without knowing the tokens were there. Use theme colors (primary.main, secondary.main, secondary.light) instead.
- VolunteersPage has a raw <button> styled with inline padding, green background and radius, used for "Print roster". That is a hand-rolled MUI Button, and it accounts for two of the findings by itself. Replacing it removes both.
- SettingsPage uses a gray #6b6b6b that matches no token. Use text.secondary, which already maps to the muted token.
- The search TextField in VolunteersPage has only a placeholder, so it has no accessible name. Add an aria-label or inputProps.

Fix first, in order:
- Swap the "Print roster" button for <Button variant="contained">.
- Replace the hex values in ShiftCard, StatusChip and SettingsPage with palette entries, and the px paddings with sx spacing units.
- Add aria-label="Search volunteers" to the TextField.

No config changes needed: nothing here looks like noise.
