## Interpretation

This is the baseline before any new feature. The score fell from 98 on 2026-10-26 to 95, but no code got worse: the updated scanner now flags unitless numbers such as padding: 20, and that accounts for all 10 new findings. The 9 findings from the last run are unchanged.

- Token discipline is the only real drift: 18 of 19 findings. Nothing is invented and nothing imports a competing library, so imports and API fidelity stay at 100.
- Hardcoded colors that already exist as tokens are the old pattern: the green border in ShiftCard, the amber pair in StatusChip and the green button in VolunteersPage. Use primary.main, secondary.light and secondary.main.
- The new unitless findings are mostly literal sizes already listed in src/design-system.md: the 32px avatar and 14px text, the 8px progress bar, the 360 and 560 max widths and the 13px caption. These are one-off layout values, not tokens, so they may be noise. The two that are not: InfoTile padding 20 and marginBottom 12, which should be spacing units 2.5 and 1.5.
- VolunteersPage.tsx has the most findings (8), led by the hand-rolled Print roster button. A MUI Button removes its padding, background and radius findings at once.
- One accessibility finding remains: the roster search field has a placeholder but no accessible name.

Fix first: swap the raw button for Button, replace hex values with palette keys, then add an aria-label to the search field.

## How this was measured

Static checks only, no model calls: imports, API fidelity (components and props against the real exports of the design system package), token discipline (hardcoded colors and sizes) and static accessibility. Checks are adapted from [open-design-system-bench](https://github.com/christophhdesign/open-design-system-bench) (MIT). A dimension that could not be measured shows n/a and is left out of the score, never counted as a pass.

What it does not check: documentation, design rules or guidelines, Figma, Storybook, hand-built components that imitate a design system one (a custom button built from a `div`), or duplicate components. It compares code against the design system package's component list and the token values, nothing more.
